# Composition System
## How 16Signals Looks

This document does not describe style.

It describes how every viewport is composed.

The purpose is not to create a beautiful landing page.

The purpose is to create confidence before the visitor consciously reads.

Every screen should feel designed by someone who understands engineering, publishing, and evidence—not marketing.

If the Creative Direction defines the brand's philosophy, this document defines its physical behavior.

---

# Core Principle

The page should never feel "designed."

It should feel carefully arranged.

Visitors should experience the interface the same way they experience reading an exceptional essay, examining an Apple product, or reviewing a well-prepared court exhibit.

The visitor should never notice decoration.

They should only notice clarity.

Every decision exists to reduce cognitive effort.

Nothing exists simply because empty space felt uncomfortable.

---

# The Golden Rule

Design the page like an editorial publication.

Never design it like SaaS.

Every viewport is a magazine spread.

Not a dashboard.

Not a feature list.

Not a marketing website.

If the layout can be mistaken for a startup template, start over.

---

# One Viewport = One Thought

Each screen exists to communicate exactly one idea.

Never explain two ideas inside the same viewport.

Never split attention.

The visitor should immediately know:

"What is this screen trying to tell me?"

If the answer is not obvious in under two seconds, the composition failed.

---

# Composition Hierarchy

Every viewport follows exactly the same hierarchy.

Primary Object

↓

Secondary Object

↓

Supporting Evidence

↓

Silence

Never introduce additional competing elements.

Every viewport has one visual hero.

Everything else supports it.

---

# Visual Weight

Every composition should distribute attention intentionally.

Approximately:

70% Primary Message

20% Supporting Artifact

10% Interface

The interface should never compete with the narrative.

Buttons are not heroes.

Navigation is not a hero.

Icons are never heroes.

---

# Negative Space

Whitespace is not empty space.

Whitespace is structure.

Empty areas create confidence.

The larger the claim, the more space it deserves.

Never fill space because it feels empty.

The absence of objects is often the object.

If adding another element makes the composition more "interesting," remove it.

---

# Editorial Grid

Every scene is built around one invisible editorial column.

Nothing should float randomly.

Objects should align to invisible structure.

The visitor should never consciously notice alignment.

They should simply feel that everything belongs.

Margins are generous.

Rhythm is consistent.

Alignment is more important than symmetry.

---

# Eye Movement

The interface guides the eye.

Never force exploration.

Every viewport should naturally produce this journey:

Headline

↓

Artifact

↓

Evidence

↓

Scroll

The visitor should never ask where to look next.

---

# Camera Language

Every scene should feel photographed.

Not illustrated.

Imagine an invisible camera observing a single object.

Objects are isolated.

Objects breathe.

Nothing overlaps unnecessarily.

Nothing floats without reason.

Every viewport could become a printed poster.

---

# Object Hierarchy

Objects earn attention.

Nothing receives equal importance.

Large objects must communicate meaning.

Small objects carry precision.

Decorative objects do not exist.

If an object has no narrative purpose, remove it.

---

# Density Rhythm

The homepage alternates between breathing and examination.

Breathing

↓

Evidence

↓

Breathing

↓

Evidence

↓

Breathing

The visitor should never experience continuous information density.

Silence makes evidence believable.

Dense artifacts feel more valuable after quiet scenes.

---

# Artifacts

Artifacts are the product.

The product is not the interface.

The report is the hero.

Evidence is the hero.

Annotations are the hero.

Real data is the hero.

Everything else exists to frame them.

Whenever possible:

Show.

Never describe.

If a claim can be visualized using a real artifact, remove the paragraph.

---

# Motion Composition

Motion exists only to reveal understanding.

Never animate decoration.

Never animate for delight.

Every animation answers one question:

"What became understandable because this moved?"

If the answer is "nothing," remove it.

---

# Interaction Philosophy

Scrolling is reading.

Not exploration.

The visitor should never feel they are navigating software.

They are progressing through an argument.

Every scroll should feel inevitable.

Not surprising.

---

# Progressive Disclosure

Never reveal everything immediately.

Every viewport contains something discovered only after commitment.

Examples:

• evidence appears
• annotation expands
• citation connects
• artifact becomes readable

Nothing dramatic.

Only quiet reward.

The page should respect curiosity.

---

# Composition Rhythm

Large.

Quiet.

Dense.

Quiet.

Detailed.

Quiet.

Confident.

The rhythm is more important than animation.

---

# Trust Through Restraint

Premium interfaces remove.

Average interfaces add.

Every new component must justify itself.

Every decoration spends credibility.

Every unnecessary pixel weakens trust.

Default answer:

Remove it.

---

# Interface Presence

The interface should almost disappear.

Navigation should feel infrastructural.

Buttons should feel inevitable.

Controls should never become visual attractions.

Users should remember the product.

Not the UI.

---

# Premium Heuristics

A premium viewport has:

• one dominant object
• one supporting object
• obvious hierarchy
• generous margins
• precise alignment
• restrained motion
• meaningful emptiness
• real artifacts
• no visual noise

If a viewport contains five equally important things, it contains none.

---

# Anti-Patterns

Never generate:

• feature grids
• benefit cards
• icon rows
• centered startup heroes
• floating dashboards
• glassmorphism
• AI gradients
• glowing objects
• decorative particles
• background illustrations
• fake analytics
• dashboard screenshots inside laptops
• abstract geometric backgrounds
• random circles
• meaningless lines
• decorative 3D

These patterns reduce trust because they communicate software marketing instead of engineering credibility.

---

# The Final Test

Before considering any viewport complete, remove the logo.

Ask:

Could this belong to any AI startup?

If yes—

the composition failed.

Then ask:

Could this only belong to the company that reads evidence?

If yes—

ship it.

---

# Design Goal

The visitor should never think:

"This looks beautiful."

They should think:

"This company seems serious."

Then:

"They understand engineering."

Then:

"I trust them enough to keep reading."

Trust is the visual product.

Everything else is interface.
